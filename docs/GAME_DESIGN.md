# 게임 설계 문서 (초안 v0.2)

> 메타버서스 위시의 1:1 덱빌딩 구조를 바탕으로, **진영 시스템**과 **별 강화 시스템**을 더한 온라인 카드 대전.
> 표시 ⚠️ 는 아직 정해지지 않았거나 확인이 필요한 항목.

### v0.2 변경점
- 화폐 단위: 큐브 → **원**
- 기본 무기 이름 변경: 단검 → **권총**, 롱 소드 → **소총**, 전쟁망치 → **돌격소총**
- 소총 5원/3 피해, 돌격소총 8원/5 피해. 각 무기는 **처음 구매되는 2장이 +1원**
- 일시 강화는 한 차례 **최대 3장**, **기본 공급 카드는 강화 불가**
- 행동카드마다 **행동력 비용**(0 또는 1) 표시
- **중립 카드 19장** 추가
- 진영 무기 "표준 소총"은 기본 소총과 이름이 겹쳐 "제식 기관단총"으로 변경

## 1. 기본 구조

| 항목 | 값 |
|---|---|
| 인원 | 1:1 온라인 대전 |
| 승리 조건 | 후공 차례가 끝날 때(라운드 끝) 판정. 한쪽만 체력 0 이하면 상대 승, 둘 다 0 이하면 체력이 높은 쪽 승, 같으면 무승부 |
| 체력 | 캐릭터마다 다름 (50~60 범위) |
| 시작 덱 | 돌 6장 + 권총 4장 = 10장 ⚠️ 비율 조정 가능 |
| 손패 | 차례 종료 시 5장 뽑기 |
| 선공 | 무작위. 선공은 1턴째 별을 받지 않는다 (후공 보상) |

### 카드 종류
- **재화카드 (노랑)**: 구매단계에 내서 원을 얻는다. 행동력 소모 없음.
- **무기카드 (빨강)**: 공격단계에 내서 피해를 준다. 행동력 소모 없음.
- **행동카드 (파랑)**: 행동단계에 낸다. 카드 왼쪽 위에 **행동력 비용**이 적혀 있다.
  - **⚡0**: 행동력 없이 낼 수 있다.
  - **⚡1**: 행동력 1을 쓴다.

### 용어
- **제거**: 카드를 게임에서 완전히 없앤다 (덱 압축).
- **얻는다**: 거래소에서 원을 내지 않고 가져와 버린 더미에 둔다 (따로 적혀 있으면 그곳에).
- **구매가**: 카드 왼쪽 아래 숫자. 거래소에서 사는 데 드는 원.

## 2. 경기 준비: 카드 입고 (드래프트)

1. 각 플레이어는 **진영 1개**와 그 진영의 **캐릭터 1명**을 고른다.
2. 후보 카드 8장 = **진영 카드 5장 + 캐릭터 전용 카드 3장**.
3. 이 중 **4종류**를 골라 거래소에 입고한다. (상대에게 비공개로 동시에 선택)
4. 중립 카드 풀(19종)에서 무작위로 ⚠️ **2종**이 이번 경기의 중립 거래소 카드로 공개된다. 입고 화면에서 미리 보여준다.
5. 거래소 = **기본 공급 카드** + **중립 카드 2종** + **내 4종** + **상대 4종** (공용 거래소). ⚠️ 공용/각자 전용 결정 필요
6. 기본 공급이 아닌 카드는 종류마다 ⚠️ 8장씩 쌓인다.

### 기본 공급 카드 (항상 거래소에 있음, 강화 불가)
| 카드 | 종류 | 구매가 | 효과 |
|---|---|---|---|
| 돌 | 재화 | 0 | +1원 |
| 은괴 | 재화 | 3 | +2원 |
| 금괴 | 재화 | 6 | +3원 |
| 권총 | 무기 | 0 | 1 피해 |
| 소총 | 무기 | 5 | 3 피해 |
| 돌격소총 | 무기 | 8 | 5 피해 |

### 무기 초기 할증
- 각 무기는 경기에서 **처음 구매되는 2장이 구매가 +1원**이다. (소총 6원 → 6원 → 이후 5원, 돌격소총 9원 → 9원 → 이후 8원)
- 할증은 **구매**에만 적용. 카드 효과로 "얻는" 경우는 할증이 없고, 처음 2장 수에도 세지 않는다.
- 할증 횟수는 **두 플레이어 합산**으로 센다. (먼저 사는 쪽이 비싸게 사는 대신 빨리 강해짐)
- ⚠️ 권총(0원)과 진영·중립 무기카드에도 적용할지 — 제안: 소총·돌격소총에만 적용

## 3. 차례 진행

원작의 기원단계는 **없음**. 대신 차례 시작 시 별이 찬다.

```
[차례 시작] 별 +1 (최대 5)
   ↓
[행동단계] 행동력 1로 시작, 행동카드 사용 (⚡0 카드는 행동력 없이)
   ↓
[구매단계] 구매 1, 재화카드로 원을 얻고 거래소에서 구매
   ↓
[공격단계] 무기카드로 상대에게 피해
   ↓
[정리] 낸 카드·손패 전부 버림 → 5장 뽑기 → 상대 차례
```

- 별 사용은 **내 차례 중 어느 단계에서나** 가능.
- 뽑을 덱이 비면 버린 더미를 섞어 새 덱을 만든다.
- 남은 원과 행동력, 구매는 차례가 끝나면 사라진다.

## 4. 별 강화 시스템

| 비용 | 효과 | 지속 | 제한 |
|---|---|---|---|
| ★ 1 | **일시 강화**: 손패의 카드 1장을 이번 차례 동안 강화판으로 쓴다 | 이번 차례 | **한 차례 최대 3장** |
| ★ 4 | **영구 강화**: 손패의 카드 1장을 영구히 강화판으로 바꾼다 | 경기 끝까지 (그 카드 한 장만) | — |

- 별은 내 차례 시작마다 +1, **최대 5개**. 5개일 때 얻는 별은 버려진다.
- **기본 공급 카드(돌·은괴·금괴·권총·소총·돌격소총)는 강화할 수 없다.**
- 진영·캐릭터·중립 카드는 모두 강화판 효과를 가진다.
- 이미 영구 강화된 카드는 일시 강화도 할 수 없다.
- ⚠️ 영구 강화도 일시 강화 3장 제한에 포함할지 — 제안: 포함하지 않음

## 5-2. 진영: 뉴로 연합

> **콘셉트**: 행동카드 위주. 행동력을 늘려 행동카드를 연달아 내고, **이번 차례에 낸 행동카드 수**에 따라 보상이 커진다.
> 행동카드가 주는 피해는 무기 피해와 합쳐져 공격단계가 끝날 때 한 번에 들어간다(방어 차감 동일).

|---|---|---|---|---|
| **시냅스 점화** | 0 | 2 | +1 행동력, +1 카드 | +2 행동력, +1 카드 |
| **신경망 동기화** | 1 | 4 | +2 카드. 이번 차례 행동카드를 3장 이상 냈다면 +1 행동력 | +2 카드, 조건 시 +2 행동력 |

## 5-3. 진영: 리간드 왕국

> **콘셉트**: 별로 싸운다. 별을 모으고, 쓰고, 그 별로 카드를 강화해서 힘을 얻는다.
> "쓴 별"(turnState.starsSpent)에는 일시 강화·영구 강화·카드 효과로 쓴 별이 모두 들어간다. 카드 효과의 무료 강화는 별을 쓰지 않으므로 세지 않는다.

## 5-4. 진영: 빈센트 공화국

> **콘셉트**: 빚으로 자원을 미리 당겨 쓰고, 그 빚을 관리한다.

### 빚 규칙
- 각 플레이어는 **빚**(0 이상의 정수)을 가진다. 빚은 특정 카드 효과로 생긴다.
- **빚이 1 이상이면 카드를 구매할 수 없다.** 카드 효과로 "얻는" 것은 구매가 아니므로 가능하다.
- 빚은 **구매단계에 원으로 갚는다**(갚은 만큼 원이 줄어든다). 화면의 "💸 빚 갚기" 버튼.
- 그 밖의 벌칙은 없다.

### 진영 카드 (5장)

| **신용 대출** | 행동 | 0 | 4 | +2 카드, 빚 +2 | +3 카드, 빚 +2 |

## 7. 구현 계획 (DeepSeek 워커 작업 단위)

**기술 구성**: JavaScript(ES 모듈) 모노레포, 테스트는 Node 내장 `node:test`. 빌드 단계가 없어 워커 작업이 단순하다. 타입은 JSDoc 주석으로 적는다.
- `engine/` — 순수 게임 로직 (서버·클라이언트 공용, 테스트 대상)
- `server/` — Node.js + WebSocket, 방 생성/입장, **서버가 판정** (치트 방지)
- `client/` — 브라우저 UI

카드는 코드가 아니라 **데이터(JSON)로 정의**하고, 효과는 공용 효과 함수(카드 뽑기, 원 얻기, 제거, 피해 등)를 조합한다. 진영·중립 카드를 계속 늘려도 엔진을 고칠 필요가 적어진다.

워커 작업이 30단계 제한에 자주 걸렸으므로, 한 작업은 파일 3~5개 이내로 쪼갠다.

| 순서 | 작업 | 확인 방법 |
|---|---|---|
| 1 | 저장소 뼈대 + 엔진 상태 모델 (덱, 손패, 버린 더미, 거래소) | 단위 테스트 |
| 2 | 차례 진행 (행동→구매→공격→정리), 행동력 비용, 기본 공급 카드, 무기 할증 | 단위 테스트 |
| 3 | 카드 정의 데이터 형식 + 효과 시스템 | 단위 테스트 |
| 4 | 별 시스템 (일시 3장 제한 / 영구 강화, 기본 공급 강화 불가) | 단위 테스트 |
| 5 | Section 8 카드·캐릭터 구현 | 카드별 테스트 |
| 6 | 중립 카드 19종 구현 (두 번에 나눠서) | 카드별 테스트 |
| 7 | 드래프트 (8장 중 4종 고르기 + 중립 2종 공개) | 단위 테스트 |
| 8 | 랜덤 AI + 밸런스 시뮬레이터 (1000판 승률) | 스크립트 출력 |
| 9 | WebSocket 서버 (방, 동시 선택, 상대에게 숨길 정보 걸러내기) | 통합 테스트 |
| 10 | 클라이언트: 입고 화면 | 브라우저 확인 |
| 11 | 클라이언트: 대전 화면 | 브라우저 확인 |

워커에게 허용할 명령: `npm install`, `npm test`, `npm run sim`
